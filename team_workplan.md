# План работ команды (2 участника) — Работа в единой ветке `main`

Этот документ фиксирует рабочие договорённости нашей команды из двух человек, критические ответы организаторов из чата соревнования и пошаговый план задач.

## 1. Главные инсайты из ответов организаторов и памятки NeuralDeep (КРИТИЧНО!)

1. **Бюджет = 100 000 токенов (`BUDGET=100000`):**
   - Бюджет передаётся контейнеру в переменной окружения `BUDGET` (например, `BUDGET=100000`).
   - Прокси **не сообщает** остаток бюджета, а при превышении лимита просто перестаёт отвечать. Наш `run_agent.py` уже настроен читать `os.environ["BUDGET"]` и вести собственный точный счётчик `input/10 + output + reasoning`.
2. **Детерминированное решение без LLM разрешено официально!**
   - Вопрос из чата: *«Можно ли решать часть задач детерминировано без LLM?»* — Ответ организаторов: **«Можно решить все, если получится»** (при этом сам харнесс обязательно должен быть построен на базе `openJiuwen`).
   - Это даёт нам колоссальное преимущество: задачи `search`, `data_analysis` и `math` (а также простые шаблонные баги в `coding`) мы можем решать чистым Python-кодом внутри компонентов харнесса за **0 токенов**, оставляя все `100 000` токенов бюджета на самые сложные задачи `coding`!
3. **Все финальные задачи будут строго тех же 4 типов (`coding`, `data_analysis`, `math`, `search`):**
   - В финальном `task.json` уберут только поле `"expected"`, а поля `"task_id"`, `"task_type"`, `"instruction"`, `"reward"` и `"check"` **останутся доступны агенту**. Сложность и структура будут похожи на примеры из `task-dir.zip`.
4. **Как оформлять ответ и невыполнимые задачи:**
   - Файл `answer.txt` создаётся **строго рядом с `task.json`** (`/data/tasks/<task_id>/answer.txt`).
   - Если задача **невыполнима** (её нельзя точно решить при имеющихся данных) — **файл `answer.txt` создавать НЕЛЬЗЯ** (за пропуск баллы не дают, но мы не тратим на неё токены).
5. **Ограничение API NeuralDeep (Правило 2 IP и лимиты):**
   - Базовый URL: `https://api.neuraldeep.ru/v1` (до 60 запросов в минуту, до 16 параллельных потоков).
   - **ВНИМАНИЕ:** С одного ключа команды можно работать **максимум с 2 разных внешних IP-адресов одновременно**! Если случайно отправить запрос с 3-го IP (например, включить VPN на ноутбуке или запустить тест на внешнем сервере, пока оба участника работают из дома), ключ **автоматически заблокируется на 60 минут**. В личном кабинете `hub.neuraldeep.ru` можно выпустить дополнительный ключ, но все они делят общую квоту аккаунта.

## 2. Как мы работаем с Git (БЕЗ веток, всё в `main`)

Мы **не создаём отдельные ветки** — оба работаем напрямую в `main`. Чтобы мы никогда не перезаписывали код друг друга, файлы проекта жёстко поделены по папкам:

| Правило | Участник 1 (Agent Core & Solvers) | Участник 2 (Planner, Unsolvable Filter & Dataset) |
| :--- | :--- | :--- |
| **Твои папки (редактируешь только их)** | `harness/agents/*`, `harness/sandbox/*` | `harness/planner/*`, `scripts/*`, `trajectories/*` |
| **Общие файлы (менять только по согласованию в чате)** | `harness/config.py`, `run_agent.py`, `Dockerfile`, `requirements.txt`, `README.md` | `harness/config.py`, `run_agent.py`, `Dockerfile`, `requirements.txt`, `README.md` |

### Алгоритм каждого пуша (строго соблюдаем!):
1. Перед тем как делать коммит, подтяни свежие изменения напарника:
   ```bash
   git pull --rebase origin main
   ```
2. Добавь свои изменённые файлы, закоммить и запушь в `main`:
   ```bash
   git add harness/agents harness/sandbox   # (или harness/planner scripts для Участника 2)
   git commit -m "кратко что сделано"
   git push origin main
   ```
3. **Сразу после `git push` напиши напарнику в Telegram/чат:** *«Запушил обновление в `main` (описание), сделай `git pull`»*.
4. Напарник сразу делает `git pull --rebase origin main` и смотрит изменения.

Если в цепочке ссылка ведёт на несуществующего человека или компанию, либо нужного поля в `.md` файле нет — сразу возвращать `status="UNSOLVABLE"` за 0 токенов!

Если в вопросе требуют отфильтровать по несуществующей колонке или в файле некорректные числа — сразу возвращать `status="UNSOLVABLE"` за 0 токенов.
